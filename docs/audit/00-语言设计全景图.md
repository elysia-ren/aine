## 2. 语言组成全景(九域)

### A. 值语义与内存模型
- **总原则(V5.8 冻结)**:"语义拥有优先,编译器借用优化,显式借用高级化"。三层:用户语义层(String/Vec/…)、编译器实现层(Owned/Borrowed/Compiler View/Copied/Materialized)、高级控制层(&T/&mut/move/unsafe)。
- **Owned 语义**:String 永远拥有;`str` 退位;`str_view` 编译器内部专用(D7:用户源码/文档/诊断一律不得出现)。
- **Compiler View(§7)**:按值参数满足视图化条件时编译器自动以视图实现(D1 四条件:只读/未逃逸/可追踪/非泛型)。
- **Materialization(§9)**:三档成本;物化不是语义错误(§8.3);禁止隐式大型 Clone(§10)。
- **实现现状**:Rust 宿主为直接求值(值语义 + COW 式 push 克隆);**Compiler View / 视图化 pass / Materialization 诊断阈值(D2: 64KB/1MB)未实现** → 此子域整体 ≈ 只有意图。
- 依赖:D1←D5;D2←D6;实现载体:宿主(值语义部分)、C 后端(值语义部分)。

### B. 类型系统(T1.0 正式规范)
- 类型集合:i32/i64/u8-u64/usize/f32/f64/bool/char/String;Vec<T>/Map<K,V>(有序,键恒 String)/Option<T>/Result<T,E>/元组/&T &mut T/命名类型/Unknown/Error(污染抑制)。
- 渐进类型:无法确定时安全回退 Unknown;错误码体系 T3001-T3010。
- 字面量默认类型表(整数 i32、浮点 f64、[] → Vec<Unknown>)。
- 实现现状:宿主 typeck 完整实现(含 Unknown/Error 回退、Ref 类型);C 后端为推断式发射(无独立 typeck,靠 var_info/base_type 链)。
- ⚠ 待验证一致性:`char` 类型 vs `s[i]` 产 1 字符 String(D15 字符模型下两者关系)。

### C. 函数、参数与生命周期
- 参数三模式(§22):普通按值(编译器可内部 Borrow)/`move` 显式转移/`&T`·`&mut T` 高级精确。
- 生命周期(§23):**用户语法无生命周期参数**;编译器内部维护 Ownership/Borrow/Escape/Region/Drop/Capture。
- 多来源返回(§24)+ D2 View-eligible 规则与物化阈值。
- 闭包(§25 + D14):统一函数类型 `fn(A,B)->R`;**捕获即快照**(创建时 env.snapshot());闭包复制=快照独立复制。
- 实现现状:宿主=快照语义真实实现;C 后端=非捕获闭包→函数指针,**捕获闭包一等传递为登记在案的已知限制**(D14.4);`move` 参数解析存在(parser 9 处),语义执行状态 `待验证`;`&T` 在 C 后端无引用类型系统(仅 push 取址等内部用途)。

### D. 错误处理与资源
- Option/Result/`?` 传播(§45);`try/catch` 仅 FFI/平台异常/`#[catchable]`(D9:默认 panic 不可捕获,catchable 仅限 unsafe/FFI 模块)。
- `defer`(§27 + D13):所有退出路径含 panic unwinding 按 LIFO 执行;defer 内再 panic = abort。
- 实现现状:宿主=defer 真实实现(run_defers)、TryCatch 实现;**C 后端=try/catch 零实现**;defer 语句 C 路径 `待验证`(alparse/alee 无 SDefer 处理痕迹,宿主 AST 有 Defer(Expr))。C 路径 Result 载荷已修复(Err 带载荷,55d6d8d 之前批次)。

### E. 并发(Future/Task/go)
- §28-32:Future/Task/go{}/go!{}/Task 边界/取消;D4 Send/Sync 字段级自动推断 + `#[not_send]`;跨任务需 snapshot(§35)。
- 实现现状:**双实现均为同步占位**——宿主 `Expr::Go` = 同步执行块(注释明言真实并发为运行时 TODO);C 后端 SGo = 内联块。Send/Sync 检查、Task 边界、取消:**未实现** → §28-32 + D4 整域 = 只有意图(语法占位已存在)。
- 注意:这是设计承诺与实现差距**最大**的域,验收依赖 §71.6/§72(Phase 3)。

### F. UI 与状态
- @state/ui{} 语义(§33-43 + D3):State Target 与 Task-owned payload 分离;State 写入=Consume/Store;ui{} 内禁嵌套 go{}、禁捕获外部借用;事件回调 `(Event)->()` 或 `->Result<(),UiError>`;组件身份(§41)。
- @global(§44 + D8):全局 State Slot;**声明位置=模块顶层 `@global let mut x: T`;写入只能经 UI Domain Operation 或受控消息;后台任务不得直接写/借用**;读取 UI 内直读、任务需 snapshot;热重载按类型保留。
- 实现现状:宿主/C 后端均将 ui{} 编译为过程式渲染 + 消息循环(C 路径 `ui_run()`);**@global 实现为普通全局变量 + 直接赋值(任意函数可写,979ad6f 刚修复其写回语义)——与 D8 的写入规则(仅 UI Domain Operation)存在实现偏差**;@state/State Storage 运行时、组件身份、热重载:`待验证`(倾向未实现)。

### G. 模块与标准库
- module/import;stdlib 63 章定义简单 API 与高级 API(§62-63);std/json 等 stdlib 文件存在(stdlib/json.aine)。
- 实现现状:双实现均支持 module 展开(flatten);stdlib 覆盖度 `待定量验证`。

### H. 编译器架构与优化体系(V5.8 的核心工程承诺)
- §12-21(约 800 行):Value Aine Graph → VIR → 跨函数/跨模块语义摘要(Summary)→ 精度五级(Level 0-5)→ 组合(§17)→ 缓存与失效(§60-61)→ 分析预算(§59)→ Optimization Explain(§58,诊断模板 F2104 风格)。
- D6 架构不变量:**摘要精度只影响生成代码质量,绝不改变可观察语义**。
- D10 Codegen:**承诺 LLVM**;1.0 前 ABI 不稳定承诺。
- 实现现状:实际后端 = **Aine→C→zig cc**(非 LLVM);VIR/Summary/精度/预算/Explain/缓存:**均未实现**(valueal_lite 字符串累加改写与 value_semantics 是局部雏形);双后端差异本身是 D6 不变量的天然测试床。

### I. 平台与工具链
- Language Veil(§52,六语言表面切换)/Source Map(§53,T51)/跨平台(§64,D11:桌面 Skia 优先,移动 1.1)/发布系统(§65-66)/AI 退出核心工具链(§67-68)。
- 实现现状:Veil(src/veil.rs)与 SourceMap 宿主有实现;移动端/发布系统未启动(Phase 6,与登记簿一致,非缺陷)。

## 5. 阶段一初步发现(仅记录;定性归阶段二/三)

1. **[承诺-实现] D10 Codegen 后端**:登记簿定稿"采用 LLVM",实际落地为 C→zig cc。要么是登记簿缺一条过渡决策(D10.5?),要么实现偏离承诺——需在账本补一条"现实路线及回归 LLVM 的触发条件"。
2. **[承诺-实现] D8 @global 写入规则**:决策规定"只能经 UI Domain Operation 或受控消息写入;后台任务不得直接写",双实现均为**任意函数直接赋值**(且 979ad6f 刚修复其写回语义使其真正生效)。这放大了攻击面:D8 试图堵的安全模型绕过通道现在是敞开的。
3. **[承诺-实现] D8 语法**:决策文本 `@global let mut x: T`,实际语法 `@global var/let`(且 mut 性由 var/let 区分)——语法细节登记与实现不一致。
4. **[过时条款] D15 已知分歧**:登记簿"C 后端暂维持字节形态…列为后续项"已被 66c1ef4(字符语义统一)解决,登记簿未更新——账本应迁移为"已验证"。
5. **[覆盖缺口] C 后端 try/catch 零实现**:§47/D9 的双实现差分必挂项;defer C 路径待验证。
6. **[覆盖缺口] 并发域整体只有意图**:§28-32 + D4 双实现均为同步占位。Phase 3 验收(§72)前无碍,但账本必须明示"语法已占位、语义未定义-未实现",防止"能写 go{} 就以为有并发"。
7. **[规模标注] VIR/Summary 体系(§12-21)约 800 行设计 = 只有意图**:这是设计文档中最大的未实现块;D6 不变量(精度不影响语义)目前由"没有精度机制"平凡满足。
8. **[文档一致性] 登记簿迁移目标写《Flow_*.md》,实际文件为《Aine_*.md》**——命名迁移未同步。
9. **[一致性待查] `char` 类型 vs D15 字符模型**:Type_System 列 char 为独立类型;D15 说 s[i] 产"第 i 个字符"(实现为 1 字符 String)。char 与 1-char String 的互转规则需要在规则总表闭合。
10. **[一致性待查] 整数字面量默认 i32 vs C 路径 long long 混用**(now_ms 等 C 运行时函数返回 long long;Aine i32=int)——跨类型边界规则需闭合。
11. **[实现缺口,审计外挂账] jsontest.aine 自举编译失败**(al_map_eq 前导码缺失 + `var x = x` 复合表达式自引用变体未走 __s_ 临时)——属实现缺陷非设计缺陷,修复不阻塞审计。
