> **阶段六产物**:差分验证的基建清单、已验证项、缺口与新增要求。
> **方法**:同一语料 → 宿主解释器(`aine run`)与 C 后端(`aine build` + zig cc)各跑一遍 → stdout/exit code **字节级 diff**。分歧 = 审计发现(宿主为参考实现,M-5)。

## 5. 差分运行器(建议形态)

```
flowc/tools/difftest.py
  输入: conformance/cases/*.aine(每文件 = 断言 + 期望 stdout 注释)
  步骤: aine run X → out_host
        aine build X → exe → out_c
        diff out_host out_c → 分歧报告(文件/行/期望/两路实际)
  输出: 分歧清单(喂 02 清单)+ 通过率(喂 03 基准)
```

宿主与 C 的诊断文案差异(运行时错误信息)应**排除在 diff 外**(仅对齐 stdout 语义行与退出码),否则噪音淹没信号。

## 6. 优先序

1. **P0-1/P0-2 修复后立即使 conformance 进 C 路径**(当前任何全量差分都会先挂溢出/defer)。
2. difftest.py 运行器 + 现有 7 文件 + 本会话沉淀片段入库。
3. 按 §3 缺口表补语料,每闭合一条规则 = 一个用例(01 总表的证据列直接引用用例名)。
4. E-4 交错模拟器作为 E 域实现的前置工程单列。
