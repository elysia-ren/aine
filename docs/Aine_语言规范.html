0本规范的地位与读法

本规范是 Aine 语言的正式正文。它以 2026-11 语言设计审计的结论为事实基础:每一条规则都有类型标签、管辖域、成熟度与证据指针;凡实现尚未覆盖的设计,一律以徽章如实标注,不作修饰。

本规范取代《Aine 语言完整设计方案定稿版》(V5.8)作为正文的组织形态。V5.8 的冻结决策不因重写而失效——它们已按原意融入各章,并经《设计决策登记簿》(D1–D15)逐条可追溯。审计产物(成熟度总表、问题与风险清单、验证基准)见 docs/audit/。

成熟度徽章

每条规则右缘标注其证据成熟度,六档:

徽章含义
已验证双实现对拍(宿主解释器 × C 后端)字节级一致,有常驻回归语料
已闭合定义、边界、失败路径与交互均已明确;单实现覆盖或有登记限制
已定义规则已明确写出;实现或边界尚未完全覆盖
只有意图设计目标存在,语法可能已占位,但语义未定义、未实现。能写出不代表能用
未涉及本规范有意不涉及(均为有意识决定,非遗漏)
定稿提案语义优化轮(SD 系列)新定稿,已实现或已登记,待正式批准迁入正册
读法约定:规则编号 A-3(域字母+序号);类型标签 定义/操作/例外/管辖/元规则——对应规则在体系中的职能,而非实现状态。

1语言定位与设计原则

Aine 是面向原生应用开发的独立语言:采用现代静态语法,但由编译器承担所有权复杂度;语言面向应用语义,独立性由语义层(值语义 / Compiler View / 语义摘要 / Task·UI Domain)证明,不依赖表面语法与任何先辈语言的差异。

1.1 五条核心原则(冻结)

#原则严格含义
§3.1显式边界,隐藏内部复杂度普通开发者只面对拥有值;编译器内部表示(str_view、Region、Escape)不出现在用户源码、文档与诊断中
§3.2安全默认默认行为取安全一侧;放开需要显式动作(move / &mut / unsafe)
§3.3复杂性藏在编译器,而不是运行时分析、消除、摘要发生在编译期;运行时不背分析税
§3.4确定性优先同一源码在任何实现、任何精度、任何优化等级下行为一致(元规则 M-6 的原则来源)
§3.5新语法必须有高频收益低频构造走库与既有机制;每次显式化升格都登记其强制标注的代价

1.2 三层内存模型(冻结)

语义拥有优先,编译器借用优化,显式借用高级化。
层谁面对内容
用户语义层所有开发者String / Vec<T> / 命名类型 —— 永远是拥有语义
编译器实现层仅编译器Owned / Borrowed / Compiler View / Copied / Materialized —— 自由选择,不可观察
高级控制层高级开发者&T / &mut T / move / unsafe —— 显式写出才存在

2元规则与规则类型

本规范的全部规则按职能分为五类(波你尼体系衍生的类型学):定义规则(赋予技术含义)、操作规则(描述行为的主干)、例外规则(显式收窄某条操作规则)、管辖规则(声明覆盖一组规则的域,其延伸范围即作用域)、元规则(规定其余规则如何解释)。一条规则的含义不只来自它的措辞,还来自它与系统中其他规则的关系——因此每条规则的编号与管辖域在本规范中始终显式。

2.1 冲突消解元规则(paribhāṣā)

当两条规则对同一情形都给出指令时,按以下元规则裁决,按序适用:

#元规则内容
M-1具体优先于一般特殊规则在其环境真包含于一般规则环境时,自动凌驾于一般规则(Elsewhere Condition;可递归收窄)
M-2显式优先于隐式用户显式写出的指令压过编译器推导的默认策略
M-3安全默认优先于便利§3.2 在冲突场景的具象化
M-4后定稿优先于先定稿同一对象被两次定稿时,以较新的登记为准;登记簿必须记录该裁决
M-5宿主解释器为参考实现双实现分歧时,以 Rust 宿主解释器的行为为语义基准;C 后端须对齐
M-6优化失败不是语义错误任何分析精度、优化成败、缓存状态的组合,均不得改变程序的可观察行为
元规则 M-4 的首个判例:§25(捕获推导 Borrow→Copy→Move)与 D14(捕获即快照)冲突,裁决 D14 胜,§25 相应段落已按此修订(见 §7.4)。

3词法文法

3.1 源文件与空白

源文件为 UTF-8 文本。空白字符为空格、制表符、回车与换行;换行是软语句终结符(见 §4.5 消歧规则)。

3.2 注释

LineComment  ::= '//' { 除换行外任意字符 }
BlockComment ::= '/*' { CommentBody } '*/'      (* 可嵌套 *)

3.3 标识符与关键字

Ident ::= (Letter | '_') { Letter | Digit | '_' }

保留关键字:

fn let var const if else for in while return break continue match struct enum trait impl where export module import move unsafe extern try catch ui render go defer true false

3.4 字面量

IntLiteral    ::= DecInt | '0x' HexDigit {…} | '0b' ('0'|'1') {…} | '0o' '0'..'7' {…}
FloatLiteral  ::= Digit { Digit | '_' } '.' Digit {…} [ Exponent ] | Digit {…} Exponent
StrLiteral    ::= '"' { StrChar | Escape } '"'
FmtStrLiteral ::= 'f' '"' { StrChar | Escape } '"'
Escape        ::= '\' ('n' | 't' | 'r' | '0' | '\' | '"' | '\'' | 'x' HexDigit HexDigit)

词法错误码:F1001 未闭合字符串、F1002 未闭合块注释、F1003 非法字符、F1004 非法/溢出数字。

3.5 运算符与装饰器

Punct ::= '(' ')' '{' '}' '[' ']' ',' ';' ':' '::' '.' '..' '->' '=>' '@' '?'
        | '+' '-' '*' '/' '%' '=' '==' '!=' '<' '<=' '>' '>=' '&&' '||' '&' '|' '^' '~' '<<' '>>'
        | '+=' '-=' '*=' '/=' '%='
Decorator ::= '@' Ident          (* @state / @global —— 项级语法,非属性 *)

4语法文法

4.1 程序

Program ::= { Item }
Item    ::= FnDef | StructDef | EnumDef | ImplDef | ModuleDef | ImportDef
          | GlobalVarDef | StateDef | UiDef

内建全局(无需声明):print read_file write_file append_file file_exists now assert(cond[, msg]) cli_args。

4.2 类型

Type      ::= PathType | RefType | TupleType | FnType
PathType  ::= Ident [ '::' Ident ] [ '<' Type { ',' Type } '>' ]
RefType   ::= '&' [ 'mut' ] Type
TupleType ::= '(' { Type ',' } ')'
FnType    ::= 'fn' '(' [ Type { ',' Type } ] ')' [ '->' Type ]

内建类型:i32 i64 u8–u64 usize f32 已定义 f64 bool char 已闭合 String Vec<T> Map<K,V> Option<T> Result<T,E>。

定义SD-1 · 整数算术域

整数算术在 64 位有符号域执行

行为
+ - * / % 一律以 64 位有符号语义求值;i32 声明的存储宽度仅在显式窄化(to_i32()、FFI 边界)时生效,窄化按二补数环绕定义(C23 modular)
失败
窄化不报错(环绕确定);除零为 panic(见 §8.4 词表)
交互
容器存储宽度:声明 Vec<i32> 等的元素槽宽 64 位(实现对齐宿主值模型)
不变量
宿主与 C 后端的整数算术结果逐位一致(双路实证:ovf 用例)
成熟度 已验证 · 来源:语义优化轮 · 税额:容器元素槽宽 2×(v1 接受)

4.3 语句

Block      ::= '{' { Stmt } [ Expr ] '}'
Stmt       ::= LetStmt | ReturnStmt | IfStmt | WhileStmt | ForStmt
             | BreakStmt | ContinueStmt | DeferStmt | TryCatchStmt | ExprStmt
LetStmt    ::= ( 'let' | 'var' ) Pattern [ ':' Type ] [ '=' Expr ]
ReturnStmt ::= 'return' [ Expr ]
DeferStmt  ::= 'defer' Expr

let = 不可变绑定,var = 可变绑定。块末表达式为块尾值。

4.4 模式与 match

MatchExpr ::= 'match' Expr '{' { Pattern '=>' Expr } '}'
Pattern   ::= Ident | '_' | IntLiteral | FloatLiteral | StrLiteral | 'true' | 'false' | Path
G1.0 边界:结构体/元组/数组/绑定模式为后续扩展(候选)。当前 match 的表面形态与主流语言一致,模式能力弱于 Rust——有意收窄,见 §16 演进表。

4.5 表达式优先级(从低到高)

AssignExpr  ::= RangeExpr ( AssignOp AssignExpr )?        (* 右结合 *)
RangeExpr   ::= OrExpr [ '..' [ OrExpr ] ] | '..' OrExpr
OrExpr      ::= AndExpr { '||' AndExpr }
AndExpr     ::= EqualityExpr { '&&' EqualityExpr }
EqualityExpr ::= RelExpr { ('==' | '!=') RelExpr }
RelExpr     ::= BitOrExpr { ('<' | '<=' | '>' | '>=') BitOrExpr }
BitOrExpr   ::= BitAndExpr { '|' BitAndExpr }
BitAndExpr  ::= BitXorExpr { '&' BitAndExpr }
BitXorExpr  ::= ShiftExpr { '^' ShiftExpr }
ShiftExpr   ::= AddExpr { ('<<' | '>>') AddExpr }
AddExpr     ::= MulExpr { ('+' | '-') MulExpr }
MulExpr     ::= UnaryExpr { ('*' | '/' | '%') UnaryExpr }
UnaryExpr   ::= ('-' | '!' | '&' | '*') UnaryExpr | PostfixExpr
PostfixExpr ::= Primary { '(' Args ')' | '.' Ident | '[' Expr ']' | '?' }

4.6 消歧与软终结规则

  • 语句默认以换行终结;块内语句无需分号。return 后换行视为空 return(同行取表达式的改进已列演进表);
  • 泛型闭括号 >> 由解析层拆分,用户按字面书写 Vec<Vec<T>>;
  • f-string 插值 {expr} 在求值阶段解析,不经二次词法(发射期禁止重新解析,演进决议 A6)。

6值语义与内存模型

管辖A-0 · 三层内存模型

用户语义层只面对拥有值

定义
赋值、实参传递、容器存储产生值的独立副本;不存在用户可见的别名
行为
变更操作(push/insert/set)产生新版本:clone-then-mutate——所有旧持有者的观察不变
不变量
编译器实现层的选择(View/Owned/Materialized)永不改变用户层可观察语义(元规则 M-6)
失败
无失败路径;例外入口仅 move/@global/extern 三处,逐条见 §7/§13/§14
成熟度 已验证 · 证据:cons.aine 双路字节一致

6.1 字符串的拥有语义

String 永远表示拥有语义。str 退位:仅作为 &str 的 pointee(高级借用视图);str_view 为编译器内部类型,用户源码、文档、诊断一律不得出现(违者编译错误)。

6.2 Compiler View 与 Materialization 只有意图

按值参数满足全部视图化条件(只读、未逃逸、可追踪、非泛型)时,编译器以零成本视图实现该参数;无法证明时回退 Materialize(拥有值),按三档成本诊断:Cheap(<64KB 静默)/Material(64KB–1MB 非阻塞提示)/Large(>1MB 强制提示)。§10"禁止隐式大型 Clone"禁的是静默复制——用户语义要求的复制(如 push 的新版本)豁免禁令,但必须进入诊断阈值体系。

本节为 V5.8 核心工程承诺,实现未启动;在实现之前,"零额外分配"是优化目标,不是语言保证(M-6:任何精度下行为一致)。

6.3 所有权状态机

编译器内部维护 Ownership/Borrow/Escape/Region/Drop/Capture。值语义下状态机退化为平凡安全:复制产生新值、变更产生新版本、无原地失效。例外入口三处:move 参数(文档性标注,SD-6)、@global(并发可达,见 §13)、extern 边界(§14)——逐条显式枚举,不隐式增加。

8错误处理与资源

8.1 三分法

通道含义恢复

8.3 defer(D13 + SD-2)

定义D13 · defer 全退出路径

defer 在所有退出路径按 LIFO 执行

范围
正常返回、early return、panic 冒泡、`?` 传播、可捕获异常
失败
defer 体内再出错 = abort 语义(立即以该错误终止,剩余 defer 跳过)
不变量

8.4 panic 构造词表(SD-5,封闭)

以下运行时错误为 panic 类,不可被普通 catch 捕获(D9),全部 abort 语义:

  1. 索引/切片越界;2. Map 键不存在;3. assert 失败;4. 运行时类型不匹配;5. 调用栈超限;6. defer 体内出错;7. 整数除零。

8.5 try/catch 边界(D9)

try/catch 仅用于 FFI exception、平台 exception 与 #[catchable] 标注的函数;普通 panic 的 catch 为编译期拒绝;#[catchable] 仅限 unsafe/FFI 边界模块。

12并发 设计冻结·实现占位

12.1 三形态(§28-30)

形态设计语义现状
let task = go { … }创建并提交结构化 Task;父作用域必须等待/取消/处理语法占位:双实现均为同步块;Task/Future 值不存在;task? 不可达
go! { … }detached 后台任务;独立处理错误;不持普通借用;不假设完成
Future<T>异步计算抽象

12.2 Task 边界与 Send/Sync(§31 + D4)

借用不得跨 Task 边界;传输数据必须 Owned / 安全 Copy / 满足 Send。Send/Sync 字段级自动推断,#[not_send] 逃生舱,FFI 类型统一 not_send,无 unsafe impl。

12.3 取消(§32)

标准异步 API 必须明确 cancellation、cancellation points、side effects、rollback;取消不自动撤销外部副作用。

实现前置链(审计裁定):Task 落地前必须先实现 D8 的 @global 写入规则(否则 @global 直接赋值的现状在并发下成为数据竞争入口);并发进入"已验证"档前必须先建确定性交错模拟器(单线程协作调度),否则占位实现与真实现之间不存在差分基准。

13UI 与状态 设计冻结·实现占位

13.1 @state(§33)

@state let mut user: User 是 Runtime-managed State Storage:含 Component ID、State Slot、生命周期、观察关系、热重载信息。不是普通变量。

13.2 ui{} = UI Domain Operation(D3)

  • ui{} 内对 @state 直读 State Storage(同域同步,无消息开销);
  • 允许:读取 Owned/Send payload、只读操作;禁止:嵌套 go{}、捕获普通外部借用、读取已 move 变量;
  • 事件回调 (Event) -> () 或 -> Result<(), UiError>;`?` 传播到回调返回值,由 UI runtime 显示(不崩溃)。

13.3 State 写入 = Consume / Store(§39)

State 写入不是赋值,是运行时两步操作。后台任务禁止直接借用 @state(§34 硬规则);跨域传输走 snapshot(§35)。

13.4 @global(§44 + D8)

全局 State Slot:仅存 Send 数据;生命周期 = 进程;热重载按类型保留。写入只能经 UI Domain Operation 或受控消息;后台任务不得直接写/借用。

实现现状(审计 P1-1,需定稿):当前双实现均为"模块顶层全局变量 + 任意函数直接赋值"(赋值与方法写回已修复生效)——这正是 D8 立法要堵的漏洞形态。Task 落地前必须实现 D8 写入规则,或显式修订 D8;禁止维持现状。

14FFI(§48-49)

extern "C" {
    fn strlen(s: CStr) -> usize
}

安全 FFI 优先 CStr/CString/CArray/ABI-safe struct;裸指针 *const T / *mut T 只进入 unsafe 块。extern 函数签名保持 C ABI(整数参数按 C int/long long 精确宽度,SD-1 例外条款);FFI 类型统一按 not_send 参与并发检查(D4)。Python FFI(§49)与移动端(D11,1.1)随平台阶段启动。
